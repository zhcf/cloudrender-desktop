# CloudRender C++ SDK

The C++ server SDK: **links nativecore directly** (DXGI capture / input injection, zero-copy) and uses **libwebrtc** for encoded streaming and data channels — the highest-performance, full-featured edition of the two server implementations.

```
server/cpp/sdk/
├── include/cloudrender/
│   ├── wire/cr_wire.hpp            # protocol layer: input/event frame codec, FNV key table (standard library only)
│   ├── capi/cr_session_api.h       # session core C ABI (the export surface of cloudrender_session.dll)
│   └── session/
│       ├── cr_source.hpp           # FrameSource / InputInjector abstractions
│       ├── nativecore_source.hpp   # nativecore adapters (frame slot + injection serialization)
│       └── cr_webrtc_session.hpp   # PeerSession (libwebrtc session layer)
├── src/
│   ├── wire/cr_wire.cpp
│   ├── capi/cr_session_capi.cpp    # cloudrender_session.dll implementation (incl. signal queuing)
│   └── session/
│       ├── cr_webrtc_session.cpp   # Offer/Answer/ICE, BGRA->I420, frame pump
│       └── nativecore_source.cpp
├── tests/                          # contract tests + session smoke (golden.txt generated by tools/golden_wire.py)
└── CMakeLists.txt
```

## Relation to the Python SDK

| Module | Python | C++ (this directory) |
|---|---|---|
| Protocol layer | cloudrender/protocol.py | **cr_wire** (byte-identical, guarded by contract tests) |
| Capture/inject | ctypes into nativecore | **links nativecore directly** (zero-copy) |
| WebRTC | aiortc | **libwebrtc** (prebuilt facade package, see build §3) |
| C ABI export | - | **cloudrender_session.dll** (loaded by the 8081 signaling shell via ctypes) |

## Build

### 1) Protocol layer + adapters (no libwebrtc needed; lowest build barrier)

Dependency: the nativecore header [`cr_api.h`](../nativecore/include/cloudrender/capi/cr_api.h); if it is not found, only `cr_wire` is built.

```bat
cmake -S server\cpp\sdk -B server\cpp\sdk\build
cmake --build server\cpp\sdk\build --config Release
```

Outputs:
- `cr_wire` (static library): the protocol layer, buildable on any platform;
- `cr_session_core` (static library): nativecore adapters + session-layer stubs (without `CR_BUILD_WEBRTC`, `PeerSession` is a no-op implementation and the headers stay usable).

On Windows, if the `cloudrender_nativecore` import library is found under `../nativecore/build/{Release,Debug}` it is linked automatically; otherwise the consumer must supply it (CMake prints a hint).

### 2) Contract tests

```bat
cmake -S server\cpp\sdk -B server\cpp\sdk\build
cmake --build server\cpp\sdk\build --config Release
ctest --test-dir server\cpp\sdk\build -C Release --output-on-failure
```

`cr_contract_test` reads `tests/golden.txt` (generated by `python tools/golden_wire.py` from the repo root; do not hand-edit the hex) and performs a **byte-level comparison** against the Python reference implementation: 8 kinds of input frames, event-channel frames, FNV-1a32 baseline vectors, decode round-trips, invalid-frame rejection. Expected output `CONTRACT_OK input=187B events=68B`.

Session-core smoke (with the DLL built; run from the repo root): `python server\cpp\sdk\tests\session_capi_smoke.py` — real capture + create_offer + signal polling; prints `SESSION_CAPI_SMOKE_OK` on success. `webrtc_smoke.cpp` / `webrtc_probe.cpp` are build-time session-layer probes.

### 3) Full session layer + cloudrender_session.dll (the media core used by 8081)

Depends on the prebuilt libwebrtc facade package (`server/cpp/third_party/libwebrtc/libwebrtc-x64-release/`, containing `include/libwebrtc.h` plus `lib/libwebrtc.dll` and `lib/libwebrtc.dll.lib`); CMake probes that path automatically and it can be overridden with `-DCR_WEBRTC_ROOT=<dir>`:

```bat
cmake -S server\cpp\sdk -B server\cpp\sdk\build -DCR_BUILD_WEBRTC=ON
cmake --build server\cpp\sdk\build --config Release
```

Outputs (in `build/Release/`):

- `cloudrender_session.dll` (target `cr_session_dll`): exports the C ABI documented in `include/cloudrender/capi/cr_session_api.h`, consumed by Python ctypes (the 8081 signaling shell);
- `libwebrtc.dll` / `nativecore.dll`: copied next to the output by POST_BUILD (the import table records the real DLL names, so they must ship alongside `cloudrender_session.dll`);
- `cr_session_core.lib` / `cr_wire.lib` static libraries.

The compile macros `CR_HAVE_WEBRTC LIB_WEBRTC_API_DLL RTC_DESKTOP_DEVICE` must match the prebuilt DLLs (otherwise factory vtable slots misalign); CMake handles this internally. Additional system libraries linked: `winmm ws2_32 secur32 crypt32 iphlpapi d3d11 dxgi`.

## Minimal usage (pseudocode)

```cpp
#include "cloudrender/session/cr_webrtc_session.hpp"
#include "cloudrender/session/nativecore_source.hpp"

cr::source::NativeCoreFrameSource source(/*monitor=*/-1, /*max_fps=*/30);  // -1 = primary monitor
cr::source::NativeCoreInjector injector;

cr::session::PeerSessionConfig config;
config.fps = 30;
config.ice_servers = {"stun:stun.l.google.com:19302"};

cr::session::PeerSession session(
    &source, &injector, config,
    {/* on_signal: forward offer/ice JSON to the client over WebSocket; on_closed: log and clean up */});

std::string sdp;
session.CreateOffer(&sdp);           // triggers on_signal("offer", ...)
session.HandleSignal("answer", sdp); // client answer/ice JSON passed in verbatim
session.StartStreaming();            // frame pump: latest frame -> BGRA->I420 -> encode & push
```

Semantics match the Python `session.py`: `FrameSource::TryTakeLatest` drops stale frames and delivers the newest; `MOVE` tries relative first, then absolute (`x*source.width()`); `WHEEL` dy×120; gamepad/touch/custom events are not handled by the v1 injector (they are already decoded by the protocol layer; see `ApplyInput`).

## Known limitations

- The encoder comes from the libwebrtc built-in factory; H264/VP8 ordering follows the factory SDP and v1 does not reorder it (cloud desktop scenarios prefer H264; an external encoder factory can be injected);
- Capture caps and privileges (desktop duplication, UIPI) depend on nativecore; see the root README and docs/integration.md.
