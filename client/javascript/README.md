# CloudRender JavaScript Client SDK

A general-purpose cloud desktop client built on browser-native WebRTC: video playback plus keyboard/mouse/wheel/touch/gamepad capture sent back — zero install. The Web demo page lives in `client/web/` (served by the servers on the same origin).

```
client/javascript/
├── src/cloudrender.js        # client SDK (ES module, zero dependencies)
├── tools/contract_test.mjs   # protocol contract test (JS <-> Python golden byte comparison)
│   └── golden.json           # generated by python tools/golden_wire.py (run from the repo root)
└── package.json
```

## Quick start

1. Start either server first (Python edition on 8080 or C++ edition on 8081; see "two runnable servers" in the root README);
2. Open the server address in a browser (e.g. `http://localhost:8080/`; the 8081 edition is `http://localhost:8081/`), click Connect, then click the video area to enter control mode;

## SDK usage

```js
import { CloudRenderClient } from "./src/cloudrender.js";

const client = new CloudRenderClient("ws://192.168.1.10:8080/ws?token=secret", {
  video: document.querySelector("video"),   // optional: auto-bind the stream
});
client.on("connected", (payload) => console.log("connected", payload));  // includes server_caps
client.on("ready", ({ resolution, codec }) => console.log("video ready", resolution, codec));
client.on("track", (track, stream) => { /* give stream to video.srcObject directly */ });
client.on("stats", (stats) => { /* fps/bitrate/rtt panel */ });
client.on("close", (reason) => console.warn("closed", reason));

await client.connect();   // runs connect->answer->ice signaling and DataChannel setup automatically

// input uplink (batched internally into binary input frames every 16ms)
client.keyDown("KeyA");
client.keyUp("KeyA");
client.mouseMove(0.5, 0.25, -3, 2);   // normalized coordinates + relative delta pair (for pointer lock)
client.mouseButton(0, true, 1);       // button: 0 left / 1 middle / 2 right
client.wheel(0, 1.0);
client.touchEvent(2, 1, 0.3, 0.4, 0.9);
client.gamepadState(0, 0b11, 3, [0.1, -0.2, 0, -0.5, 0, 0.5]);
client.sendText("Hello");
client.custom(9, new Uint8Array([0x78, 0x79, 0x7a]));
client.requestKeyframe();            // request a keyframe when the picture degrades (signaling video_lost)
```

### Events channel

The server pushes `CREV` binary frames over the `"events"` DataChannel; the SDK forwards the raw `ArrayBuffer` through the `eventframe` event, parsed with a static method:

```js
client.on("eventframe", (buf) => {
  for (const ev of CloudRenderClient.parseEventFrame(buf)) {
    if (ev.kind === 0x01) console.log("cursor", ev.x, ev.y);          // cursor_pos
    if (ev.kind === 0x02) console.log("quality", ev.bitrate, ev.fps); // quality
    if (ev.kind === 0x03) console.log("toast", ev.text);              // toast
  }
});
```

## Protocol conformance check

```bash
python tools/golden_wire.py   # run from the repo root: generates golden.json (this folder) and golden.txt (for C++)
npm test                      # byte-level comparison: input/events frames, FNV vectors, bad-frame rejection
```

Expected output: `CONTRACT_OK input=187B events=68B`. The SDK encodes/decodes identically to the Python/C++ servers (spec: docs/protocol.md).

## Browser requirements

- Modern Chrome/Edge/Firefox/Safari (native `RTCPeerConnection` + `DataChannel`);
- Public deployments must serve the page over HTTPS (with an HTTP page, `ws://` is blocked by the mixed-content policy); see docs/integration.md §1.3;
- Pointer Lock must be triggered by a user click on the video area; both relative movement and normalized absolute coordinates are covered by `mouseMove`.
